重装 Windows 11 别再手动配环境了：微软官方脚本，一条命令变干净开发机

重装完 Windows 11，真正的麻烦才刚开始：关 Widgets、关各种推荐、打开文件扩展名、装 Git / VS Code / Python / Node / .NET、再配 WSL + Ubuntu……这些事单拎出来都不难，难的是又多又碎、换台机器全重来一遍，还老漏掉某项。

微软自己受够了，直接开源了一个脚本：Windows Developer Config。官方定位一句话——“一次操作，把一台全新的 Windows 11 变成干净、无干扰的开发工作站”。

TL;DR

  • 一条命令 irm https://aka.ms/devconfig/standard/setup.ps1 | iex 就能把新 Win11 配成开发机。
  • 三档：Standard（精简）、Full（激进清理 + 全装）、单语言 workload（只装某门语言环境）。
  • 装的全是官方/主流工具：VS Code、Git、.NET SDK 10、Python 3.14+uv、Node LTS+nvm、WSL+Ubuntu、PowerToys、Cascadia 字体等。
  • 它动的不只是"装软件"，还改系统设置：关 Widgets/推荐、开扩展名/隐藏文件/深色模式、开 Developer Mode、RDP。
  • 脚本透明可审计，wsl-comfort 还能脱离 WSL 单独用到普通 Ubuntu 主机，一套终端环境多机复用。

它到底帮你装了哪些东西？

Windows Developer Config 不是一个"装某个工具"的脚本，是一整套开发环境脚手架。Standard 配置（最小档）安装/配置清单：

类别 内容
编辑器 / 代码 VS Code、Git、GitHub CLI、GitHub Copilot CLI
运行时 Python 3.14 + uv、Node.js LTS + nvm、.NET SDK 10
终端 Windows Terminal、PowerShell 7、Oh My Posh
子系统 WSL + Ubuntu
增强 PowerToys、Coreutils for Windows、Windows App CLI
外观/行为 Cascadia Mono NF 字体、深色模式、长路径支持

Full 配置（激进档）在 Standard 基础上多加了 Azure CLI、Intelligent Terminal，并做一堆系统清理和开关。

Standard 还是 Full？差别在"清理有多狠"

两档的真正区别不在"装多少软件"，在动系统默认行为动得多深。

Standard 只做轻度清理：减少开始菜单 / 搜索 / 资源管理器的推荐项，把最烦人的干扰关掉，然后装基础工具链。适合"我想要开发机，但不想大改系统"的人。

Full 是激进的：

# 关闭 / 调整
关 Widgets 小组件
关 Windows Search 的 Web 搜索结果 + 搜索亮点
关开始菜单推荐 / 账户通知
关资源管理器"快速访问"常用文件夹 + 最近文件
关同步提供商提示、隐藏蓝牙托盘图标
Edge 新标签页改空白、跳过首启欢迎
全局勿扰模式、关 Toast 通知

# 安装
在 Standard 之上加 Azure CLI、Intelligent Terminal

# 系统开关
开 Developer Mode、Windows Sudo
开 Win32 长路径、Remote Desktop
显示扩展名 + 隐藏文件
资源管理器默认打开"此电脑"
任务栏右键加"结束任务"
深色模式、PowerShell 7 设为默认终端
配 Oh My Posh + Cascadia Mono NF 字体 + Copilot Terminal Profile

一句话：Standard 保守，Full 把一台"出厂 Win11"变成"开发者取向"的系统。Full 关的东西多，如果你这台机器还要给非开发者用（比如家里人），建议用 Standard，或者只挑单语言档。

三档怎么选（决策表）

你的场景 推荐档 原因
专职开发机，彻底个人用 Full 清理够狠，系统行为全按开发者来
家庭共用机 / 想保留默认行为 Standard 只关最烦的，其他不动
只想要某门语言环境 单语言 workload 不装一大堆，精准到语言

单语言档是我个人最被低估的一档。比如只要 Python：

. \Workloads\python\install.ps1
# 自动装 Python 3.14 + uv

只要 Java：

. \Workloads\java\install.ps1
# 自动装 Microsoft Build of OpenJDK 25 LTS

覆盖 TypeScript、Python、Go、Rust、Java、PHP、.NET、SQL、PowerShell、WinForms、WinUI 3、Windows App CLI。临时要个干净环境跑某门语言，不用整台机器全配。

一条命令的背后，你要知道它动了什么

irm ... | iex 看着简单，实际是个 PowerShell 远程脚本执行 + 一堆系统变更。用之前心里要有数它动了哪些"不可逆"的开关：

  • 关掉的（Widgets / 推荐 / 通知）——可逆，但你要知道关了
  • 开 RDP（远程桌面）——Full 档会开，家用机注意端口暴露
  • 开 Developer Mode / Sudo——开发者要，但系统行为有变化
  • 改默认终端为 PowerShell 7——如果你习惯 cmd 会不适应

建议：跑之前先开一个虚拟机 / 新盘试一遍，确认它改动的项都符合预期，再上主力机。脚本本身是微软官方仓库、代码可审，比来路不明的优化器强，但"一键改系统"这类事，先隔离环境试总没错。

它和那些"Win11 优化软件"不一样

Windows 上不缺一键优化器，但大多第三方面、功能黑箱、还常夹带广告。Windows Developer Config 的差异是：

  • 微软官方开源（github.com/microsoft/WindowsDeveloperConfig），仓库可审
  • 目标纯粹：只做"开发工作站"，不碰驱动、不装全家桶
  • 透明可回退：每一步都是标准系统设置 / 官方包管理器动作，出问题能定位

对"我就想要一台干净开发机、不想要第三方软件塞满"的人来说，这是目前最省心的官方方案。

常见问题

Q1: 这条命令要在管理员 PowerShell 跑吗？

A: 是。涉及装系统组件、改注册表、开 RDP，用管理员权限 PowerShell 执行。

Q2: 会破坏我现有的软件吗？

A: 它做的是安装/配置/关推荐，不卸载你已有软件。但 Full 会改系统默认行为，已有定制过的机器先虚拟机试。

Q3: 单语言档和完整档能混用吗？

A: 能。你可以先跑单语言 workload 只装某门语言，需要时再跑 Standard/Full 补齐，动作是幂等叠加的。

Q4: WSL Comfort 是什么，必须用吗？

A: 可选。它专门把 WSL 里的 Linux 终端环境配好（zsh/bash、Starship、fzf、ripgrep、fd、bat、eza 等 + 字体 + Terminal Profile），支持无人值守。不装 WSL 就用不上。

Q5: 我不用 WSL，能单独跑那份 shell 配置到 Linux 上吗？

A: 能。comfort-shell-bootstrap.sh 可以脱离 WSL，单独用于普通 Ubuntu 主机，一套终端环境多设备复用。

Q6: 它比我自己一步步装好在哪？

A: 省"又碎又容易漏"的重复劳动 + 版本是微软对齐过的组合（.NET 10、Python 3.14、Node LTS、OpenJDK 25 等），换台机器一条命令重来，不用记 20 个步骤。
