打了 7 月补丁没？Win11 有个 Bug 能把 C 盘吃到只剩渣

2026-07-25，星期六
阅读时长：5分钟
阅读人数：0
文章大纲

C 盘突然红了，不一定是你装太多软件，也可能是 Windows 自己在背后默默吞空间。

这次被点名的不是“某个第三方清理工具误报”，而是 Windows 11 24H2 / 25H2 里的一个真实系统问题。微软后来在支持页里直接写了修复说明：它会改善 CapabilityAccessManager.db-wal 的磁盘占用。翻成大白话，就是这个系统组件对应的日志文件，可能会像没拧紧的水龙头一样持续长大，把系统盘一点点喝干。

更扎心的是，这事不是“理论上可能出问题”。多家媒体实测和转述里，都提到过它能把空间吃到 500GB 以上，极端情况下甚至被写成 513GB。对一台 1TB SSD 来说，这不是“占了点地方”，这是直接把半个盘拿去当垃圾场。

这 Bug 到底在吃什么

重点在 CapabilityAccessManager.db-wal。

Windows 里有些权限、能力、应用访问记录，会落到这个组件相关的数据库日志里。正常情况下，.db-wal 这种写前日志文件会随着事务推进被回收、合并，不该无限长大。可这次问题就是它没有正常收口，导致文件不断膨胀，最后被系统盘背锅。

所以你在“存储感知”里看到的，往往不是一个名字特别吓人的病毒文件，而是很朴素的一类表现：

  • “系统与保留”突然暴涨
  • C 盘明明没装新东西，却越来越红
  • 磁盘清理、常规卸载、删下载目录都没啥用
  • 你越查越像玄学，最后发现是 Windows 自己在吃盘

这类 bug 最恶心的地方，不在于它会不会报错，而在于它安静。它不弹窗、不报警、不敲锣打鼓，等你反应过来时，盘已经快见底了。

微软认了，修也给了

这次比较关键的一点，是微软不是装死。

在 2026-06-23 的 KB5095093 预览更新说明里，微软已经明确写了：

This update improves disk space usage for the CapabilityAccessManager.db-wal file.

也就是说，微软至少承认两件事：

  1. 这个文件确实有异常占用问题
  2. 修复已经进入补丁链路

随后到 2026-07-14 左右，这个修复被更广泛地带进 7 月更新节奏里。换句话说，事情不是“某个论坛里有人喊盘满了”，而是官方更新说明里已经把刀口指出来了。

你怎么判断自己是不是中招

别急着先删系统文件。先确认现象。

最直接的办法是去看：

  • 设置 → 系统 → 存储 → 显示更多类别 → 系统和保留
  • 或者用磁盘分析工具看系统盘的大头到底是谁

如果你看到 System & Reserved 异常大，且增长很快，那就要怀疑这类问题。

如果你已经装了 KB5095093 或 7 月相关更新，但空间还是没回来，那就要看是不是旧日志还留着、或者还没触发回收。补丁修的是“继续长大”的问题，不一定自动替你把旧垃圾清掉。

现在该怎么做

很简单，按优先级排：

  1. 先确认 Windows 版本

    • 重点看是不是 24H2 / 25H2

  2. 再确认更新状态

    • 看有没有 KB5095093 或 7 月相关累积更新

  3. 如果还没更新，先补丁

    • 这比盲目清目录安全得多

  4. 如果已经中招且空间紧张，再做清理

    • 先看系统和保留占用
    • 再决定是否要进一步处理日志/临时文件
    • 不要上来就对 System32 下手，那是给自己挖坑

这事真正该提醒谁

不是所有人都该盯着这个 bug，但这几类人最好立刻看一眼：

  • Windows 11 24H2 / 25H2 用户
  • C 盘本来就不大的轻薄本用户
  • 长期不重装、也不爱清理系统盘的人
  • 公司电脑上权限不高、又经常被系统盘告急的人

这类机器最怕的不是“坏”，是“慢慢坏”。今天掉 30G，明天掉 50G，等你想起检查时，系统已经开始卡登录、卡更新、卡启动。

结尾别只记住“补丁”

这次最值得记住的，不是一个编号，而是一个很现实的提醒：

系统盘变小，不一定是你乱装东西；也可能是系统自己在偷偷吃盘。

Windows 这种事最阴的是，它会把“存储问题”伪装成“用户管理不善”。你以为是自己手欠，最后才发现，锅是微软的。

这回还好，微软认了，也修了。真正要命的是，很多人会在补丁出来之前，先花钱买新 SSD。
