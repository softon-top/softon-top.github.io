隔了一年半，LocalSend 1.18.0 终于放大招：命令行版来了

2026-08-15，星期六
阅读时长：9分钟
阅读人数：0

如果你的电脑桌面上、手机主屏上、公司办公机上都装着同一个青绿色小图标，那基本可以确定，你是那种「文件从来不发微信自己传自己」的选手。LocalSend 就是这批人手里的默认答案：跨 Windows、macOS、Linux、Android、iOS 五端，局域网直传，不走云、不压缩、不改名。

但这两年用过来，多少有点尴尬。上一版有分量的更新还停在 2025 年 2 月，一晃过去一年半，日常里够用，也没啥新花样。直到 2026 年 8 月 11 日，1.18.0 突然更新，一次性把好几个「早就该做」的功能全端了出来。

最重要的一件事：命令行版本终于来了

在 LocalSend 的历代版本里，这次的头号亮点毫无悬念——CLI 支持。

以前你想在一台没有图形界面的机器上收发文件，只有两个选项：一个是硬装个虚拟桌面把 App 拉起来，一个是老老实实用 scp。前者笨重，后者……你但凡跨过 Windows 和 macOS 折腾过 SSH key，就知道那是一场需要冥想的仪式。

现在 CLI 版是这样跑的：进入交互模式，读取配置文件里的默认设备名、下载目录、监听端口，也可以在命令里覆盖；启动之后可以用热键发现附近设备、发文件、收文件；旁边同一网段的手机、笔记本会看到一台标注为 CLI 的设备躺在列表里。

对我来说最有价值的两个场景：

  • NAS：想把手机拍的一段 4K 视频丢进 Jellyfin 的媒体目录，以前要么走 SMB 挂载，要么先上传到某个云盘再拉下来，现在直接手机点 LocalSend，选中那台 NAS 的 CLI 实例，几秒完事。
  • 只有 SSH 的服务器：临时把日志文件、配置备份、一份 CSV 拉到手机看一眼——不用再折腾一次 scp + pbcopy。

CLI 打包成独立的 tarball / exe，不需要装 GUI 版本作为前置依赖。这一点很重要，意味着 Docker 镜像、树莓派、iKuai 上的软路由都能轻装上阵。

IPv6 监听：企业内网和移动网络的救星

第二个容易被忽略但同样关键的改动：1.18.0 开始支持 IPv6 监听。

日常家用 Wi-Fi 用不出感觉，但只要你在下面这几种网络里试过传文件，就会知道这条更新的分量：

  • 公司大内网被切成一堆 VLAN，同一楼层不同交换机就跨不了子网
  • 咖啡厅 / 展会 Wi-Fi 开了「AP 隔离」，同一 SSID 下设备互不可见
  • 手机热点开 IPv6 转发，笔记本靠 tether 上网

以前这种情况 LocalSend 直接摊手，因为设备发现走 UDP 多播。IPv6 支持之后，很多场景可以直接靠链路本地地址端到端通，不再需要一致的 IPv4 子网、也不用 VPN 兜底。企业办公和随身移动网络里，可用性直接上一个台阶。

「浏览器领文件」：接收端不装 App 也能收

Receive 页面新增了一个 Receive via link 按钮。

打开之后 LocalSend 给你一串本机 IP 网址（也可以扫二维码），把这串链接甩给对方，对方在任何浏览器里打开就能上传文件到你的机器——不用注册、不用装 App，甚至可以是别人家不敢乱装软件的公司电脑。

早期 LocalSend 就有「Share via link」发文件给浏览器的能力，这一版把反方向也补齐了。发和收都可以只用一端有 App，另一端只需要浏览器。对做技术支持、临时帮同事收资料的人来说，这是一条极稳的兜底通道。

校验和默认开：传坏文件的年代过去了

checksum support (enable by default)——1.18.0 默认为每一次传输启用校验和比对，收发两端算完 hash 对齐后才算成功。

以前偶尔会有玄学：截图能开，PSD 打不开；ZIP 能列目录，解压第某个文件炸掉。九成是无线信号弱、路由带宽掉包导致文件写入不完整。默认打开 checksum 之后，这种情况会直接在传输完成时报错，而不是等你到目标机器上才发现「诶怎么打不开」。

同时这一版把文件大小统一成 十进制单位（1 GB = 1000 MB），跟 macOS、iOS、Android、Linux 对齐。这个是给强迫症用户的良药——以前 Windows 端和其他端显示 1.86 GB 和 2.0 GB，一直看着别扭。

各平台的小甜点

除了上面几条主线，1.18.0 塞了一堆平台专属的小改进：

Linux 端：终于支持 CJK 中文字体，UI 里出现中文/日文/韩文再也不是方块了；换成原生窗口装饰，去掉了那条 GTK3 大 header bar，视觉上一下子紧凑不少。

macOS 端：新增 Command+, 打开设置（终于对齐 Mac 惯例）；Troubleshoot 页面多了「一键打开防火墙设置」按钮；应用启动名字从「Mac 用户看不懂的技术 hostname」换成了系统里那个「XX 的 MacBook Pro」；Dock icon 支持「App 没在跑时也能拖文本进去」。

Windows 端：LocalSend 加入了 Windows Share Sheet——在文件管理器里右键任意文件，选择「共享」，弹出的系统分享面板里直接能看到 LocalSend。这是我个人期待很久的一个改动。

Android 端：多了一块快捷面板磁贴，从状态栏下拉直接拉起 App；文件传输可以真正在后台跑，不用担心切个 App 就掉包。

其他杂项：自定义主题颜色（拾色器）、慢速接收方也能更快传输、重复文件命名从 file-1.txt 改为 macOS 风格的 file (1).txt、修 Mac 的 Dock 拖拽和 Share Extension、修 Android「Share via link」下载不动的老 bug。

怎么装最新版

三条路，看你在什么环境：

桌面端（Windows / macOS / Linux）

去 GitHub Release 页找对应平台的安装包：

https://github.com/localsend/localsend/releases

Linux 上 .deb / .rpm / .AppImage 都有；macOS 有 .dmg；Windows 有安装包和便携版。

CLI 版

在同一个 Release 页里往下翻，找 CLI 专用的独立 tarball / exe，跟主 App 分开发布。装完直接 localsend --help 看参数。

移动端

  • Android：Google Play、F-Droid、GitHub Release 的 APK 三种渠道都行，注意 Play 版和自签版签名不一样，混装的话要卸载重装。
  • iOS：App Store 直接搜 LocalSend。

一句话总结

LocalSend 这次不是打补丁，是补了两个大洞（CLI 和 IPv6）、加了两个小惊喜（浏览器上传、默认校验和）、顺手打磨了每个平台的细节。原本它就是「跨平台传文件」这个赛道的默认答案，1.18.0 之后，服务器、NAS 和企业内网这几块之前不太吃的场景也一并覆盖上了。

如果你还没装它，装一个；如果你已经装了，去更新。这一版的更新按钮，值得点。
