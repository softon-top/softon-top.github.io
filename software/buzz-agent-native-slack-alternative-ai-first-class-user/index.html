AI agent 终于不是一等公民了。

2026 年 7 月 21 日，Block（Jack Dorsey 的公司，背后是 Square 和 Cash App）发布了 Buzz——一个开源协作平台，口号是"人类和 AI agent 共享工作空间"。不是给 Slack 加个 bot 插件，而是从协议层就把 agent 当一等公民设计。

Jack Dorsey 在推文里说：

“we’re launching BUZZ! a new groupchat platform for teams of people and agents of all sizes, built to reduce our dependency on slack and github. model-agnostic, decentralized, self-sovereign, and open source.”

一周内 GitHub star 破 13,700。

TL;DR

  • Buzz 是 Block 发布的开源 agent-native 协作平台，Apache 2.0，Docker Compose 自托管
  • 核心差异：agent 有独立加密身份和频道级权限，不是共享 bot token 的插件
  • 架构基于 Nostr 协议，去中心化，支持 Git 仓库连接和自动化工作流
  • 对比 Slack/Mattermost：Buzz 的 agent 是"团队成员"而非"集成插件"
  • 自托管门槛低：Postgres + Redis + MinIO，Tauri 桌面端覆盖三大平台

Buzz 到底是什么？

Buzz 看起来像 Slack——频道、线程、回复、emoji 反应、DM，该有的都有。但它解决的问题不一样：

Slack 的问题：AI agent 通过 bot token 接入，权限是应用级的，不是用户级的。你给 bot 开了 #general 权限，它就能看到 #general 所有消息。agent 没有自己的身份，没有独立的权限边界，没有完整的审计日志。

Buzz 的方案：每个 agent 有自己的 Nostr 密钥对，频道级权限控制，每个操作都有加密签名和审计日志。agent 是"团队成员"，不是"集成插件"。

特性 Slack + Bot Mattermost + Plugin Buzz
Agent 身份 共享 bot token 共享 webhook 独立加密密钥对
权限粒度 应用级 应用级 频道级
审计日志 有限 有限 完整，每次操作加密签名
自托管 ❌ ✅ ✅
Agent 原生设计 ❌ ❌ ✅
Git 集成 通过 app 通过 plugin 原生

架构拆解：Nostr + 容器化

Buzz 的协议层基于 Nostr——去中心化、加密、无需中心服务器。Block 工程博客说：

“Where existing standards stopped, we specified agent authorization, access, memory, control, accounting, Git signatures, device pairing, and related machinery.”

技术栈：

组件 作用
Nostr 协议 去中心化通信层，加密消息中继
PostgreSQL 持久化存储（频道、消息、用户）
Redis 实时消息缓存和 pub/sub
MinIO/S3 文件存储（图片、附件）
Tauri 桌面客户端（macOS/Windows/Linux）
Docker Compose 一键自托管部署

设计亮点：agent 的"记忆"（memory）、“控制”（control）、“计费”（accounting）都在协议层定义，不是应用层 hack。这意味着任何兼容 Nostr 的 agent 都能接入 Buzz，不绑定特定框架。

Buzz 的差异化：不是"更好的 Slack"，而是"为 agent 时代设计的聊天平台"。Slack 的 bot 模型是 2013 年的设计，Buzz 把 agent 当一等用户是 2026 年的设计。

Docker Compose 自托管实战

环境准备

一台 2C4G VPS，Ubuntu 22.04，Docker + Docker Compose。

# 克隆仓库
git clone https://github.com/block/buzz.git
cd buzz

# 配置环境变量
cp .env.example .env
# 编辑 .env，设置域名和密钥

# 启动
docker compose up -d

初始化用户 

# 每个用户需要自己的 Nostr 密钥对
# 在桌面客户端生成，分享公钥给管理员
# 从服务器添加用户
docker compose exec app ./buzz-cli add-user --pubkey <用户公钥>

踩坑 1：Nostr 密钥对是 Buzz 的身份基础。没有密钥对就无法加入。桌面客户端会自动生成，但管理员需要手动添加公钥。

添加 AI Agent 

# Agent 也有自己的密钥对
docker compose exec app ./buzz-cli add-agent --name "code-reviewer" --pubkey <agent公钥>

# 给 agent 分配频道权限
docker compose exec app ./buzz-cli grant-access --agent "code-reviewer" --channel "#dev"

踩坑 2：agent 的权限是频道级的。你给 agent 开了 #dev 权限，它只能看到 #dev 的消息。这与 Slack bot 的"全有或全无"完全不同。

验证运行 

# 检查服务状态
docker compose ps

# 查看日志
docker compose logs -f app

Agent 工作流实例

一个典型的 Buzz agent 工作流：

  1. Code Review Agent 加入 #dev 频道
  2. 开发者推送代码到连接的 Git 仓库
  3. Agent 自动拉取 diff，生成 review 评论
  4. 评论以 agent 身份发到 #dev 频道，带有加密签名
  5. 人类开发者回复，agent 继续跟进

整个流程中，agent 的每次操作都有完整审计日志——谁、什么时候、做了什么、签名是什么。

常见问题

Q1: Buzz 和 Nostr 社交有什么区别？

A: Nostr 是去中心化社交协议（类似 Twitter），Buzz 用 Nostr 做底层通信但加了企业功能：频道权限、agent 身份、Git 集成、审计日志。Buzz 是团队协作工具，不是社交网络。

Q2: 能对接哪些 AI agent 框架？

A: 协议层兼容 Nostr 的 agent 都能接入。不绑定特定框架——你可以用 OpenClaw、Claude Code、或自己写的 agent。

Q3: 数据安全吗？

A: 消息通过 Nostr 加密中继传输，自托管模式下数据存在你自己的 Postgres。Agent 操作有加密签名和完整审计链。

Q4: 和 Slack 比有什么劣势？

A: 生态早期——没有 Slack 那么丰富的 app 目录、集成和社区插件。但 agent 原生设计是 Slack 没有的。

Q5: 能迁移现有 Slack 数据吗？

A: Buzz 目前没有官方 Slack 导入工具。新建团队建议直接迁移，存量团队可并行运行过渡。

Q6: 移动端体验如何？

A: 目前主要是 Tauri 桌面端（macOS/Windows/Linux）。Web 客户端可用，但移动端原生应用还在路线图上。

Q7: Block 会持续维护吗？

A: Block 工程博客明确开源承诺，Apache 2.0 许可证。即使 Block 停止维护，社区可以 fork 继续。去中心化协议也降低了单点依赖风险。
