Claude Code 用 Kimi、Codex 用 DeepSeek：一个本地网关把 80 个编程助手并成一套

你是不是也卡在这个循环里：Claude Pro 订阅只能喂 Claude Code，Codex 想用 DeepSeek 得改一次 JSON，改完想换回去再改一次。客户端越多，机器上躺的配置文件越多，每个厂商的密钥、base URL、模型名各写一套。直到某个晚上你对着第 8 个 agent 的配置文件，突然不想干了。

magpie 就是来终结这个循环的。一句话：让任意编程助手跑在任意厂商的模型上，全部从一个菜单栏面板切。

TL;DR

  • magpie 是 Go 写的本地网关，监听 127.0.0.1:3425，双向翻译 OpenAI Chat / OpenAI Responses / Anthropic Messages / Gemini 四种协议。
  • 它只改每个 agent 配置文件里"那一个值"，注释、顺序、格式全部保留；切回原模型自动还原。
  • 订阅（Claude Pro/Max、ChatGPT Plus、Copilot、Gemini）能被共享给其他 agent，多账号按意图/顺序/轮询/额度自动故障转移。
  • 和 CC Switch（改配置派）、CCR（可编程网关派）、New API（服务端派）分工不同，本文给选择表。
  • 默认每天向 PostHog 发一次匿名计数，DO_NOT_TRACK=1 可关；隐私掩码默认关闭，需要手动开。

它到底在解决什么麻烦？

先把问题摆清楚，不然你会觉得"这工具我不用"。

每个 AI 编程助手都把模型配置写在自己的文件里，格式互不相通：Claude Code 用 settings.json 里的 Anthropic 字段，Codex 用 config.toml，Gemini CLI 又是另一套。更糟的是协议层就不兼容——Codex 只会说 OpenAI Responses，Claude Code 只会说 Anthropic Messages，两家不说同一种话。

于是你陷入三重割裂：

  • 模型割裂：想给 Claude Code 换个便宜模型，得先确认对方说不说 Messages。
  • 订阅割裂：你付了 Claude Pro 的钱，它只在 Claude Code 里值钱；Codex 一分钱也花不到。
  • 账号割裂：额度用尽时，你得手动改配置、重启会话，才能换下一个账号。

magpie 的做法是在你和厂商之间插一个本地网关。所有 agent 都只跟 127.0.0.1:3425 说话，翻译和路由交给网关。你机器上的 ~/.claude/settings.json 里那行 base URL，从 https://api.anthropic.com 变成 http://127.0.0.1:3425，剩下的什么都不用动。

四种协议互译，是它最硬的那块

官方 README 的原话是：网关说 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Gemini，并在它们之间双向翻译，流式、工具调用和推理过程都带上。

这句话是 magpie 和"改配置工具"的本质区别。CC Switch 默认模式只重写目标配置的键值，让 Claude Code 直连你选的厂商——如果那个厂商不说 Messages，就没得聊。magpie 的网关永远说 agent 想听的那种话，再把请求翻译成上游能懂的那种。

实测场景很直白：

magpie codex moonshot/kimi-k2.5              # Codex 跑 Kimi：Codex 说 Responses，网关翻成 Kimi 能听的形式
magpie claude deepseek/deepseek-v4-pro       # Claude Code 跑 DeepSeek：说 Messages，网关翻给 DeepSeek
magpie group add "Opus anywhere" models=claude/claude-opus-5-5,copilot/claude-opus-5.5 routing=smart
magpie claude group/opus-anywhere             # 路由组：多订阅轮流上，额度耗尽自动换，agent 看不到报错

配置改写是原子的：README 明确写了"comments, order and formatting stay as they were"。你手写的那堆注释不会被打乱，切回 agent 自己的模型时旧值自动写回。

订阅共享：让 Claude Pro 也能喂 Codex

这是 magpie 最"爽"的部分，也是我最想提醒你谨慎的部分。

官方文档里，Subscriptions 一节写得很明白：一个你已登录的 agent 本身就是"一个带模型的订阅"，所以 magpie 把它作为 provider 提供给其他所有 agent。支持共享的订阅包括：

  • Claude：直接驱动本地真实的 claude 二进制，把 agent 的工具通过 MCP 桥接过去
  • Codex / ChatGPT：你的 ChatGPT 套餐模型，用在其他任意 agent 里
  • GitHub Copilot、Gemini (Code Assist)、Antigravity、Grok (SuperGrok) 等

还有 Daily warm-up：可以给每个 Claude 和 ChatGPT 账号设定 5 小时窗口的启动时间，或者在上一个账号重置的瞬间自动开跑——把订阅的"额度时钟"榨到极致。

听起来很美。但请把风险一并读完：

  • 账号条款：把订阅共享给非官方客户端，是否违反厂商服务条款，需要你自己判断。magpie 官方 README 只写了"Thanks to Kimi for supporting magpie and the open source community"，并没有替任何厂商背书。
  • 本地凭证读取：magpie 会去读 agent 的登录文件（Claude Code 和 Codex 的文件、Keychain）来发现订阅。不想让它读，去 Settings → Privacy → Subscription accounts 关掉，或 magpie accounts discovery off。
  • 路由组的隐含成本：一个组里塞的账号越多，故障转移越"无声"，你也越容易忽略某个账号正在被高频调用。

我的建议：先拿一个你不心疼的账号试，跑一周看额度消耗和报错率，再决定要不要把主力订阅也接进来。

同类的四个工具，别再搞混

选题时我特意把这几个项目全查了一遍，因为它们经常被混为一谈。先看数据（GitHub API，2026-11-17）：

项目 语言 协议数 星数 License 默认端口
magpie Go 4 种双向翻译 37,649 MIT 3425
CC Switch Rust Routing 模式下 4 种 154,973 MIT 15721
CCR (claude-code-router) TypeScript 3 种统一端点 38,191 MIT 3456
New API Go OpenAI/Claude/Gemini 兼容 52,034 AGPL-3.0 服务端

CC Switch（farion1231/cc-switch，Tauri 2 桌面应用）走的是"改配置派"：默认 Direct 模式只重写目标配置的键值，先备份，MCP servers、skills、prompts 统一管理，90+ 厂商预设。它的 Routing 模式是可选的，默认不开。适合"我就想手动给每个工具换厂商，别给我加中间层"的人。

CCR（musistudio/claude-code-router）走"可编程网关派"：127.0.0.1:3456，agent profile 把 agent 接到网关，用 header/body 条件、rewrite、retry、credential pool、有序 fallback 决定每个请求去哪。适合"我要写规则、要审计每次调用成本"的人。

New API（QuantumNous/new-api）是"服务端派"：自托管 LLM 网关，OpenAI/Claude/Gemini 兼容 API、模型路由、访问控制、用量与成本记账。它服务的是团队/多用户场景，不是"我台机上三个 agent 互换模型"。

magpie 的位置很清楚：一个本地网关 + 协议翻译 + 订阅共享 + 账号故障转移，目标是"你机器上的每一个 agent 都能用任意模型，且额度耗尽时无感切换"。官方 alternatives 页自己也承认三者重叠、各有所长，可以并排用。

  • 支持 agent 数：README 列了 80+ 个名字，从 Claude Code、Codex、Gemini CLI 到 OpenClaw、Cursor CLI、Zed、Cline、Qoder、Kimi Code 等；只显示你机器上已安装的。
  • 网关端点：127.0.0.1:3425，任何吃 base URL 的客户端都能直接指过来：
export OPENAI_BASE_URL=http://127.0.0.1:3425/v1     OPENAI_API_KEY=magpie
export ANTHROPIC_BASE_URL=http://127.0.0.1:3425     ANTHROPIC_API_KEY=magpie
export GOOGLE_GEMINI_BASE_URL=http://127.0.0.1:3425 GEMINI_API_KEY=magpie
  • 隐私掩码：默认关闭；开启后密钥、邮箱、密码等在本地替换成 {{API_KEY_xxx}} 占位符再发出，回复里换回；值只在内存，不落盘；掩码跑不起来时请求直接 503，绝不原文外发。
  • 每日计数：release 构建每天向 PostHog 发一次 magpie active，含随机 id、版本、系统、agent/provider/model 计数（各最多 50 条），不含名字、URL、密钥、提示词。源码构建从不发。DO_NOT_TRACK=1 或 noStats: true 全关。

常见问题

Q1: magpie 会不会偷我的 API Key？

A: 不会主动上传。README 的 Privacy 一节写明：prompts、replies、keys、accounts 只发给你配置的 provider；默认每天发一次的只有匿名计数，且可用 DO_NOT_TRACK=1 关。但注意：你的 agent 请求经过网关，网关自然"看得到"请求内容——这是所有本地网关的共同前提，CCR、CC Switch Routing 模式同理。

Q2: 我需要开隐私掩码吗？

A: 看场景。掩码默认关闭；开了之后 .env、日志里的 token 会在本地被替换，agent 和你文件里仍是真值，厂商看不到。代价是"想问这个 token 为什么被拒"这类任务做不了，需要把该值加进 Never mask。建议先关，觉得有需求再开。

Q3: 装了 magpie，Claude Code 会不会变得不是原来的 Claude Code？

A: 会有一点变化。magpie 通过驱动本地真实的 claude 二进制并桥接工具，但请求走的是 127.0.0.1:3425 而非直连 Anthropic。协议是 Anthropic Messages，官方说流式、工具调用、推理都翻译，但具体到某个 beta 字段是否无损，只有实测能答——这正是它发版这么密的原因。

Q4: 和 CC Switch 到底选哪个？

A: 一句话：手动给每个工具换厂商、想保留原配置原样 → CC Switch；想让每个 agent 走同一个翻译网关、还要订阅共享和账号故障转移 → magpie。两者都 MIT，可以并存，magpie 的网关也能作为"能吃自定义 base URL 的 provider"被别的工具调用。

Q5: 为什么它 3 天发 310 个版本，是不是不稳？

A: 是高速迭代，不是不稳定。看 open_issues_count 有 4,395（2026-11-17），说明社区反馈量大、维护者在快速跟进。建议：生产环境别追最新版，锁一个你验证过的版本；个人玩具随便追。

Q6: 免费吗？有隐藏收费吗？

A: 开源 MIT，软件本身免费。你要花的是你自己的 API Key / 订阅费用。注意 README 底部列了赞助商标识，以及 usemagpie.ai/go/… 形式的推广链接会计数点击——那是站点行为，与本地网关功能无关。

Q7: 我只想让 Codex 用 DeepSeek，不想搞网关，有别的路吗？

A: 有。直接改 Codex 的 config.toml 指到 DeepSeek 的 OpenAI 兼容端点即可，代价是每次换模型都要手动改。magpie 的价值就在于把"改一次"变成"点一下"，并在额度耗尽时自动换——如果你只有一次性需求，别装。
