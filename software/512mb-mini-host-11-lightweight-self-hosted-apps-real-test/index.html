512MB 小主机实测：11 款超轻量自托管工具，哪些真能跑，哪些是纸面参数

十美元，512MB 内存，4GB 存储，四核 ARM Cortex-A53。

这是开发者 Laurens Bosscher 在 小众软件 分享的 OpenStick 小主机配置。他买来一台原本刷不了机的高通 4G 上网卡，刷上 Debian，用 Podman 跑起了广告过滤、AI 助手、RSS 阅读、服务器监控一整套服务，并且列了 11 个工具的"参考内存占用"。

这类清单我见过太多，绝大多数的问题是：数字是抄的，不是跑出来的。你照着装完，发现 512MB 根本不够——因为清单算的是单个工具的"最低内存"，没算你同时开几个。

所以我把这份清单逐项拉回官方仓库和 README 核对了一遍，把纸面参数和真实可用范围分开，再给你一个 512MB 的装法。

TL;DR

  • 11 个工具里，Beszel / Dozzle / Gatus / Diun 是真正的 10-20MB 量级，可以无脑装
  • 清单把 AdGuard Home 和它的 fork “AdGuard Home Next-Gen” 当成两个工具算，实际是同一件事，预算要按一个 40MB 算
  • 512MB 内存下真正的天花板不是工具数量，是 Docker 本身——容器运行时 + 每个容器的开销，先扣掉 100MB 才轮到工具
  • 广告过滤选 AdGuard Home（38k stars，成熟），别选 22 stars 的 Next-Gen，除非你要验证它
  • 想复制这套方案，先想清楚你的设备是"常开"还是"按需唤醒"——内存账本对前者成立，对后者不成立

先说清楚：这台设备到底是什么

OpenStick 不是新硬件，是一类基于高通 MSM8916 芯片的 4G USB 上网卡。原本插电脑上只能当调制解调器用，OpenStick 项目（1.2k stars）把它逆向移植到了主线 Linux，刷 Debian、postmarketOS 都能跑。

所以这套方案的真实意义不是"买台小主机"，而是：你已经有一台吃灰的 4G 上网卡，或者一台 512MB 的树莓派/旧安卓机，别扔，它能跑一整套家庭服务。

硬件参数（来自原文）：

项目 参数
处理器 四核 ARM Cortex-A53 @ 1GHz
内存 512MB RAM
存储 4GB eMMC
系统 Debian Linux
容器 Podman
价格 约 10 美元（含运费）

⚠️ 一个坑：OpenStick 项目完全开源但禁止商用，README 明确写了售卖镜像、批量售卖设备都算违规。自己玩没问题，别拿去做生意。

关键前提：内存账本要先扣 Docker 的开销

这是原清单最大的遗漏。

它列的是"工具本身占多少 MB"，但你的 512MB 不是从零开始用的。实际账本是：

总内存 512MB
- Debian 系统底噪       约 60-80MB
- Podman 运行时底噪     约 30-50MB
- 每个容器的额外开销    约 5-15MB/个
= 真正能给应用的内存    约 350-400MB

也就是说，你只有大约 350-400MB 的可支配内存。清单里 11 个工具加起来写的是 5+40+64+8+20+10+10+22+10+9+40 ≈ 238MB，看起来富余，但加上 11 个容器开销（110-165MB）就直接顶到 400MB 了。

结论：512MB 不是"能装 11 个工具"，是"能装 5-6 个真正常开 + 2-3 个按需启动"。

这也是为什么我一直说 Docker 对小内存设备是双刃剑——它解决了依赖地狱，但每个容器都要一份运行时开销。真要抠内存，用 systemd 直接跑二进制，或者 Beszel 官方那样把 hub 和 agent 都做成单文件，比容器省。

我把清单里每个工具的官方仓库拉了一遍，核对 stars、语言、最近更新。以下数据来自 GitHub API（2026-11-12 抓取）。

硬伤一：清单把一个东西算了两遍

第 2 项 AdGuard Home 和第 11 项 AdGuard Home Next-Gen 是同一个功能的两份实现。

  • AdGuard Home：38k stars，AdguardTeam 官方，成熟
  • Next-Gen：22 stars，作者 LaurensBosscher 自己的 fork，README 原文写的是"memory-efficient DNS blocklists for OpenStick/routers (fork of AdGuardHome)"，2026-11-01 才创建

原文明确说"这属于作者自己的项目，与前面介绍的官方 AdGuard Home 功能存在重叠"。但列在 11 款清单里，读者会以为这是 11 个不同工具——实际是 10 个。

这不是大问题，但你应该知道：想省内存，选官方 AdGuard Home 就够了。除非你就是想测作者这个 fork，否则 22 stars 的项目不要当主力。

硬伤二：ZeroClaw 的 64MB 需要打问号

ZeroClaw（33k stars，Rust，Apache-2.0）是个很有意思的项目——单 Rust 二进制，接 20+ 个 LLM 提供商，30+ 个消息渠道，工具调用走 shell/浏览器/HTTP/MCP。

但它的定位是功能完整的 AI Agent 运行时，不是"轻量脚本"。64MB 这个数字，原清单没给出处，而一个要跑 LLM 对话 + 浏览器工具 + MCP 的 agent，空闲 64MB 是可能的，跑起来带上下文窗口时一定不止。

我的判断：可以装，但把它当成"最占内存的那个"来预留预算，别按 64MB 算。真要用，留 100MB 余量。

其他几个：基本可信，但各有前提

  • Fusion RSS：2,364 stars，TypeScript。RSS 阅读器是 Node 生态，22MB 这个数字大概率是"应用内存"，Node 运行时底噪另算。想装，先当 40MB 算。
  • Beszel：27k stars，Go，官方 README 直接写 “Lightweight: Smaller and less resource-intensive than leading solutions”，还专门列了 swap 和 ZFS ARC 的内存统计。这个最可信。
  • Dozzle vs Beszel 的分工：原文说得对——Beszel 看资源占用，Dozzle 看容器日志。两个不重复，都值得装。

512MB 到底怎么装：我的两套方案

方案 A：常开服务（推荐，约占 250MB）

适合设备 24 小时开机的场景。

服务 内存预算 理由
AdGuard Home 40MB 全家 DNS 过滤，常驻才有意义
Beszel (hub + agent) 20MB 监控本机和 NAS，异常告警
Dozzle 12MB 出问题时看日志，比 SSH 快
Gatus 10MB 服务挂了自动告警
Cloudflare Tunnel 15MB 免公网 IP 暴露服务
合计 约 97MB + 容器开销 加 5 个容器开销约 60MB，共 157MB

剩下 200MB 富余，可以再加 Shiori（书签）或 Fusion RSS。

方案 B：按需启动（适合旧手机 / 电池供电）

设备不常开，用的时候再拉起来。

# 只常驻最关键的
AdGuard Home        40MB
Cloudflare Tunnel   15MB
Beszel              20MB

其余服务用 podman run 需要时手动起，或者写成 systemd timer 定时跑一次就退出（Gatus、Diun 都支持这种用法）。

为什么强调这点：内存账本对"常开"成立，对"按需"不成立。你一台旧安卓机插在充电座上 24 小时开，和一周唤醒一次，装的东西应该完全不同。本站之前写过旧安卓机跑 Docker，那套方案的重点就是不要常驻。

清单之外，我建议补的一个：内存监控本身

这份清单里有个有趣的现象——11 个工具里 3 个是监控（Beszel 看资源、Dozzle 看日志、Gatus 看可用性）。

这很说明问题：小内存设备最容易出的故障是OOM（内存耗尽被系统杀进程）。而 OOM 的痕迹往往只留在日志里。

所以如果你只装一个，我会选 Beszel——它直接显示内存、swap、ZFS ARC 和每个容器的占用历史。有了它，你才知道上面那张账本表哪一行是假的。

先有监控，再谈优化。 没监控的小主机，优化全靠猜。

常见问题

Q1: 512MB 真的够用吗？

A: 够，但不是"全部常开"。扣掉系统和容器运行时，你可支配约 350-400MB，按我方案 A 装 5 个常驻服务占约 157MB，还有余量。想全装 10 个，得砍到按需启动。

Q2: 为什么用 Podman 不用 Docker？

A: 两者都能跑，Podman 无守护进程（daemonless），对小内存设备更省一点，且 rootless 更安全。但 Docker 的镜像生态更大。真要抠内存，两个都比"直接跑二进制"费。

Q3: AdGuard Home 和 Next-Gen 到底选哪个？

A: 选官方 AdGuard Home（38k stars）。Next-Gen 是作者自己的 fork，22 stars，2026-11-01 才建，功能重叠且未经社区验证。除非你要专门测它的内存优化。

Q4: 这份清单的内存数字能信吗？

A: 分工具。Beszel / Dozzle / Gatus / Diun / AdGuard Home 的数字和官方定位一致，可信；ZeroClaw 的 64MB 和 Fusion RSS 的 22MB 偏乐观，实测要留余量；两个 AdGuard 是重复计算。任何清单的内存数字都要自己跑一次 docker stats 核对。

Q5: 我没有 OpenStick，用旧手机 / 树莓派能照搬吗？

A: 能。核心约束是内存，不是硬件。512MB 树莓派 Zero 2W、刷了 Debian 的旧安卓机都适用。但旧手机要注意电池长期插电膨胀，建议拆电池直供或限电充电。

Q6: Cloudflare Tunnel 会不会泄露数据？

A: 它建的是从你设备到 Cloudflare 的出站加密连接，不需要开端口映射，攻击面比公网 IP + 端口暴露小。但流量会经过 Cloudflare 边缘节点，敏感服务建议叠加访问控制（比如本站写过的 tinyauth 认证中间件）。

Q7: 这套方案和群晖/威联通这类成品 NAS 比，意义在哪？

A: 意义在不依赖厂商。NAS 厂商停更、加订阅、砍功能你都没辙；一套 Debian + Podman 的小主机，服务全是你自己装的，迁移只要拷配置。代价是你要自己维护——这是自托管的永恒交换。
