Ladybird 首个 Alpha 发布：不 fork 任何人的浏览器，到底走到哪一步了

2026-11-26，星期四
阅读时长：12分钟

你在浏览器地址栏输入一个网址，背后是谁在读 HTML、画 CSS、跑 JavaScript？答案大概率是 Blink——Chrome、Edge、Opera、Brave、Vivaldi 全是它的壳。剩下两个名字：Mozilla 的 Gecko 和 Apple 的 WebKit。三个引擎，撑着整个现代网页。

然后 2026 年 11 月 23 日，第四个名字来了：Ladybird 首个 Alpha 正式上线，macOS 和 Linux 可下载。它不是又一个 Chromium 换皮，而是官方反复强调的「从地上长出来的新引擎，不是 fork」。

TL;DR

  • Ladybird 是 SerenityOS 分裂出来的独立浏览器项目，由非营利组织 Ladybird Browser Initiative 运营，引擎完全自研，不基于 Blink / WebKit / Gecko。
  • 2026-11-23 发布首个 Alpha，仅 macOS 与 Linux；Windows 暂无原生版，官方建议在 WSL2 里跑 Linux 版。
  • 官方自认「今天不对安全性做任何承诺」，会崩、部分网站打不开，明确请安全研究者来打它。
  • 支持 WebDriver 与 Firefox DevTools 协议，做网页开发的人最有理由装一个。
  • GitHub 仓库约 6.9 万 star、BSD-2-Clause 许可；官方路线图：2027 年 Linux/macOS Beta，2028 年面向大众的稳定版。

一个不用 Chromium 的浏览器，凭什么值得你花 10 分钟

先把话说清楚：我不是来劝你把 Chrome 卸载的。恰恰相反，Ladybird 官方自己都在说——别拿它当日常主力。项目负责人 Andreas Kling 的原话是「some websites won’t work, and it will crash sometimes」（有些网站用不了，而且偶尔会崩），安全方面更是直接摊牌：「we make no promises about security today」（今天我们对安全不做任何承诺）。

这种坦白在软件发布里很少见，反而让我想把它讲清楚。原因是它验证了一件更少见的事：一个小团队、靠捐款活着，把一个独立浏览器引擎推到了「双击就能装」的程度。在几乎所有浏览器都跑 Blink 的市场里，这本身就是个技术事件。

Hackaday 的定性很到位：Ladybird 现在是「第三个在研的主要浏览器引擎家族」。这句话的分量在于历史——2000 年代浏览器战争留下的教训是单一生态主导互联网不是好事，而 2026 年的现实是 Blink 加 WebKit 几乎吃掉一切，Firefox 已经成了局外人。Ladybird 是在这个背景下长出来的，不是玩具。

为什么不直接 fork 一个现成引擎？

Ladybird 的出身很怪：它最初是 SerenityOS 的一个组件——一个从零手写、刻意不依赖第三方库的极客操作系统。SerenityOS 有很强的「什么都自己写」文化，浏览器也跟着这个路子走。2024 年，浏览器部分被拆分出来成为独立项目，就是现在的 Ladybird。

官方 FAQ 里专门回答了一个尖锐问题：你说你独立，可你们一开始用了 SerenityOS 的代码啊？回答是：重点是从零构建新引擎，不使用来自 Blink、WebKit、Gecko 或其他任何浏览器引擎的代码。出于历史原因它用了 SerenityOS 的一些库，但分裂之后不再受「全自己写」约束，现在也会用第三方库处理常见功能——图像、音视频格式、加密、图形等，其中一些库跟其他浏览器用的是同一个。

技术栈上有个值得注意的转变：代码库起点和主体仍是 C++，但官方已宣布 Rust 作为 C++ 的继任语言，正在把子系统逐步移植到 Rust。GitHub 仓库的元数据也把主语言标为 Rust（仓库 LadybirdBrowser/ladybird，BSD-2-Clause 许可）。换句话说，这不是一个「新语言重写一切」的浪漫故事，而是老 C++ 引擎务实渐进地换心脏。

项目的钱从哪来？官网写得很直白：完全靠捐赠和赞助，组织形式是 501(c)(3) 非营利机构。赞助档位从 Copper 1000 美元到 Platinum 10 万美元一年，官网列出的赞助者里能看到 Mitchell Hashimoto、Paul Copplestone、Andreas Mähler、The Primeagen 等名字。关键条款是：所有赞助都是无限制捐赠，董事会席位和其他影响力不出售，赞助方对技术路线和产品方向没有发言权。这和浏览器市场里那笔 everyone 都知道的「默认搜索引擎位置」生意划清了界限——Ladybird 明确拒绝这类变现。

Alpha 到底能干什么、不能干什么

首次 Alpha 在 2026 年 11 月 23 日由 Kling 本人发文宣布。这是他说的「期待了很久的一篇帖子」。几个要点：

  • 平台：macOS 和 Linux。没有 Windows 构建。
  • 滚动更新通道：这是 Kling 说他自己最兴奋的部分——引擎迭代很快，以前你得自己从源码编译才能看到进步，现在普通用户能自动收到更新。
  • 崩溃处理：崩溃后你可以先读崩溃报告，再决定要不要发出去；浏览器内可以直接举报打不开的网站。
  • 开发友好：支持 WebDriver 做自动化测试，也支持 Firefox DevTools 协议。

第三方报道补充了安装细节（来源为 Hardware Busters 汇总）：Linux 有 Flatpak、Ubuntu 和 Fedora 仓库包，以及不自动更新的 tarball；Mac 端是 DMG 镜像，体积约 70 MB——对比主流浏览器的下载量，这个数字相当克制。首次启动只有三个问题：搜索引擎、标签页布局、配色主题；支持垂直标签页；新标签页目前是空白。

没有扩展、没有账号同步，我凭什么还说它值得装？

如果你问「它比 Chrome 好在哪」，答案是：现在几乎没有。没有扩展、没有书签密码同步、没有移动端、没有账号体系。第三方评测对界面的形容是「modest, but functional」（朴素但能用），Kling 自己也是这么说的。

这些缺失不是疏忽，是路线选择的必然结果。一个从零写的引擎，第一优先级只能是「把网页正确渲染出来」——HTML、CSS、JS、布局、排版，每一个都是深坑。官方月度总结里能看到他们的推进节奏：2026 年 9 月是安全加固（与 Trail of Bits 合作）、硬件视频解码；10 月是 CSS 动画、JavaScript JIT、新的 WebAssembly 引擎、界面重设计；再往前还有沙箱、下载管理、浏览历史、GPU 隔离等等。这些都是浏览器引擎的地基工程。

值得对比的是「Fork 一个现成浏览器」的路线。同一批讨论里有人提出：AI 辅助软件开发的下一个目标应该是浏览器，fork 一个开源浏览器快速魔改。反对意见也很硬：浏览器是仅次于操作系统的关键软件，几乎所有个人数据和认证信息都从它走过，信任没法轻易给。Ladybird 选的是最慢的那条路——自己写引擎，但换来的是没有历史包袱、没有谁的商业议程绑在身上。代价就是上面那张表里的一串「无」。

拿了赞助的「独立」，还算是独立吗？

浏览器这行有个心照不宣的事实：大部分「免费」浏览器的收入来自默认搜索引擎的排位交易。Ladybird 的组织设计几乎每条都在对着这个事实划线：

  • 501(c)(3) 非营利，没有股东，不需要增长。
  • 赞助是无限制捐赠，不给董事会席位，不给产品决策权。
  • 官网明说不做默认搜索交易、不发币、不做任何形式的用户变现。

你当然可以怀疑「拿了钱的独立」算不算真独立。我的看法是：制度约束比动机宣言更有说服力。不接受有投票权的赞助方、不设股权、把技术路线写成公开流程——这些是可验证的结构，比一句「我们很有良心」扎实。它也确实因此换来了社区信任：GitHub 上约 6.9 万 star、3300 多个 fork，对一个 2024 年才从 SerenityOS 分出来的项目来说，这个数字说明开发者愿意盯着它。

我的建议：现在该怎么定位它

别当生产力工具，当观察窗口。 具体分三类人：

  • 普通用户：不用动。等 2028 稳定版再说，现在装它等于自愿当测试员，还要承担官方明说的「不安全」。
  • 网页开发者：装。你的网站在第四个引擎上渲染成什么样，这件事现在只能靠真机试。它支持 WebDriver 和 Firefox DevTools 协议，验证成本低；而且你报的每个坏页面，都是在帮未来的互联网多留一条命。
  • 开源/隐私爱好者：可以装在虚拟机或备用机上把玩，但别登录银行、公司 SSO、密码管理器。官方自己都求你来黑它——被攻破了记得写报告。

有个细节挺能说明团队性格：Kling 在 Alpha 公告里直接喊话安全研究者「We want security nerds to hack it!」（我们欢迎安全极客来黑它），理由是新版浏览器被反复攻破是成长的一部分，攻破了请告诉他们怎么做到的，好去补洞。这种把「漏洞披露」写成邀请的姿态，比任何安全白皮书都更能建立信任。

常见问题

Q1: 现在能把 Ladybird 当日常主力浏览器吗？

A: 不建议。官方明说部分网站打不开、会崩、对安全不做承诺。它现在的价值是「证明独立引擎能跑到双击安装」，不是替代你手头的浏览器。

Q2: Windows 用户完全没份吗？

A: 原生 Windows 版要等引擎基础稳固后再说，不在当前优先级。想在 Windows 上体验，官方给的路径是用 WSL2 跑 Linux 版本。原生 Windows 构建存在但属实验性质。

Q3: 支持 Chrome / Firefox 扩展吗？

A: 不支持。扩展是第三方讨论里被点名最多的缺失项，官方也没有把它放进 Alpha 阶段的目标。

Q4: 它安全吗？能用来登网银、公司账号吗？

A: 别。官方原话是今天不对安全做任何承诺，还主动邀请安全研究者攻击它。真有安全需求，继续用成熟的浏览器。

Q5: 既然 Firefox 也是非 Blink 引擎，Ladybird 跟它什么关系？

A: 竞争与互补并存。Gecko 是当前唯一有规模的独立引擎，Firefox 近年份额下滑、处境尴尬；Ladybird 是后来者，目标是做第三条真正独立的路线。两者共同的价值是给 Web 标准实现多留一份多样性。

Q6: 怎么装？

A: 官网首页进 Downloads。Linux 有 Flatpak、Ubuntu/Fedora 仓库包和不自动更新的 tarball；Mac 是 DMG。首次启动会问你搜索引擎、标签页布局和主题三个问题。

Q7: 为什么不直接用 Rust 全部重写，还要留着 C++？

A: 因为它是从 SerenityOS 的 C++ 项目里长出来的，重写整个引擎等于推倒重来。官方选择的是渐进策略：宣布 Rust 为 C++ 继任语言，逐个子系统移植。慢，但不赌项目生死。
