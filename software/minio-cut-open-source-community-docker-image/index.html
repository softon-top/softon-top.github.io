MinIO 砍开源社区版、删 Docker 镜像：自建 S3 还能信谁？我把 4 个下家全跑了一遍

上周搭新环境，docker pull minio/minio 的时候卡住，回头一看——minio/minio 仓库 2026 年 4 月 25 日归档了，只读、不收 PR、不再出新镜像。十年前我在 VPS 上跑的第一套自建站图床备份就是 MinIO，当时觉得"自建 S3 这块稳了"。现在这块地基被人抽走了。

TL;DR

  • MinIO 社区版已死：2026-04-25 GitHub 仓库归档，源码之外不再有预编译二进制和官方 Docker 镜像，安全补丁断供。
  • 官方只推自家 AIStor 商业版，自建党实际在选 4 个下家：Garage、RustFS、SeaweedFS、Ceph。
  • 我最推荐 Garage：单 binary、50MB 内存起、单机即打、CRDT 多节点，对"家用 + 小团队"甜度最高。
  • RustFS 最像 MinIO 的 drop-in，但还在 1.0.0-alpha，别进生产。
  • 旧部署能跑但无上游，任何 CVE/内核升级都得自己扛——这是真正该动手迁移的信号。

MinIO 到底砍了什么，为什么是现在

不是 2026 年 4 月那一刀的事，是一整条线，时间拉出来看就懂了：

时间 发生了什么 影响
2021 开源协议 Apache 2.0 改成 AGPLv3 提供服务的一方须开源，商业公司开始绕开
2025-05 社区版删除控制台管理 UI 白嫖党少一块，企业版多一块
2025-10 停止向 Docker Hub 发布社区版镜像（RELEASE.2025-10-15T17-29-55Z 版本） 当天撞上一个严重 CVE 修复，开发者没法拉新镜像打补丁，社区炸锅
2025-12 联合创始人 Harshavardhana 在 README 宣布"维护模式" 官方明牌
2026-02 → 2026-04 仓库先归档、短暂解封、再次归档（4 月 25 日） 终局

我的判断：这不是 MinIO 一家变坏，是"公司做出好软件 → 免费分发做不起盈利 → 对核心用户开刀"的又一轮。GitHub Discussion 里有句话说得狠：“It’s not a feature issue, it’s a trust one.” 信任塌了，技术再强也没人敢下注。

自建 S3 真正要的是什么

先把需求摆出来，别被"对象存储"四个字糊过去：

  • S3 兼容 API：rclone、Restic、Kopia、Velero、Loki、MinIO 客户端、各种 aws s3 脚本能不能直接指过去，不改一行配置。
  • 单机能跑：家用 NAS / HomeLab 场景下，别一上来就要 3 节点集群。
  • 资源小：内存、CPU、启动速度，别拖垮家里那台旧机器。
  • 有上游维护：CVE 有人修、内核升级后还能跑、Docker/K8s 有人跟。
  • 免费且开源：这是整个自建叙事的底线，AIStor 一毛钱都不信。

MinIO 当年赢就在这五条全占。现在它自己把"免费且开源"这条让掉了，剩下四条，谁最贴就选谁。

4 个下家实测账本

我本地起了一套 250GB NVMe + 12C24G 的容器机，四款全装一遍，同一组脚本（rclone 备份 50GB 混合小文件 + 单次 5GB 大对象上传下载）跑，记录如下：

项目 许可证 资源占用（静默） 单机难度 多节点 S3 兼容度 我实测结论
Garage AGPLv3 ~50MB 内存 / 单 binary 20MB ★ 极简（一条命令） ★★ 中等 高 最推荐，家用甜度最高
RustFS 类 Apache 偏低 ★★ 易 弱 高（MinIO drop-in） 还在 alpha，不进生产
SeaweedFS Apache 2.0 中等 ★★★ 偏难 ★★★ 强 高 大文件 / 视频存储最稳
Ceph LGPL 高 ★★★★ 重 ★★★★ 强 高 企业级，3 节点起步，家用别碰

Garage 实测最爽。一条 docker run 起单机，控制台能直接用；多节点走 CRDT，两台之间对账、没有中心节点——这对"家里一台 + 异地一台"的场景是天选。备份脚本我直接把 MinIO 的 endpoint 改成 Garage 的，rclone 一行没动。

RustFS 名字像 MinIO，路径也最像 MinIO（它就是在 MinIO 社区版基础上重写的）。但版本还挂在 1.0.0-alpha.X，README 自己写着"未到生产等级"。适合做开发环境顶替，上生产我直接跳过。

SeaweedFS 强项是大对象：4K 视频、数据集，吞吐拉满。但它一套服务（master、volume、fsm）起来偏重，小团队用觉得"功能多到用不上"。

Ceph 一句话：企业答案。三节点起步、底层存储规划、运维知识门槛高。HomeLab 用户碰它基本是给自己找罪受。

我为什么最后选 Garage

不是"谁 S3 兼容度高谁就赢"，是这几条同时满足：

  • 一条命令起，家用 5 分钟通；
  • 内存 50MB 级，旧机器扛得住；
  • 多节点 CRDT，异地容灾不用引中心；
  • 已有真实合作社、非营利组织跑了多年生产，不是玩具；
  • 迁移：旧 MinIO 桶 rclone sync 直接搬，API 不兼容的地方极少。

如果你的场景是"大规模视频 / 数据集存储"，SeaweedFS 更合适；如果"我就要 MinIO 的路径原封不动"，RustFS 先顶一段等它出 1.0；如果是"企业多节点 + 高可用 + 强合规"，Ceph 还是正解。Garage 只是把"90% 家用和中小自建"这条最常见的需求切得最干净。

迁移要踩的几个坑

别只换软件，这几个地方容易翻车：

  • 控制台没了：MinIO 社区版 2025 年起砍了 UI，Garage 自带一个够用，但别把老习惯带过去。
  • 密钥系统要重配：MinIO 用 MINIO_ROOT_USER/PASSWORD，Garage 是 token 对，迁移脚本里这两行别共用。
  • 生命周期 / 版本化规则：S3 的 versioning 各家实现深度不一，Restic、Kopia 依赖的增量语义要先用目标端跑一遍再切。
  • minio-client (mc) 命令：大部分能用，但 mc admin 子命令在 Garage 上会报错，别写进自动化脚本。

常见问题

Q1: 我现在的 MinIO 还能用吗，要不要马上迁？

能用，旧镜像和新部署都还在跑。但"无上游"意味着 CVE 没人修、内核升级后没人保证能跑。我一般给自己 3 个月观察期，期间新桶直接开在新栈上，旧的慢慢 rclone sync 搬完。

Q2: Garage 单节点可靠吗，挂一台数据就没了？

单节点是"单点故障"，数据只有一份。家用可以接受；要多节点容灾就上 Garage 的 CRDT 多节点，两台异地对账，掉一台不影响读。别拿单节点跑关键备份。

Q3: RustFS 什么时候能上生产？

以目前 1.0.0-alpha 进度看，至少再等 2-3 个版本。现在只当开发替身，别进备份链。

Q4: 我图床走的是 Cloudflare R2，受影响吗？

不受。R2 是 S3 兼容，不依赖 MinIO。受冲击的是"自己搭 S3 给 R2 当底"或者"自建对象存储整套"的那批人。

Q5: SeaweedFS 和 Ceph 能混用吗？

技术上能，但没必要。一个环境定一种，运维心智负担别叠加。

Q6: 有没有 MinIO 的社区分叉还在更新？

有，OpenMaxIO、pgsty/minio 都试图续命，但活跃度都撑不起生产。我实测过的 4 款里，Garage 是唯一有真实生产背书且资源占用的最平衡的。
